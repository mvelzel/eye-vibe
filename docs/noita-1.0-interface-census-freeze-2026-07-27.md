# Noita 1.0 interface census: frozen test

**Frozen:** 27 July 2026, before inspecting the named 1.0 assets in the
installed WAK.

## Question

Did the public build interval in which the Eye Messages first appear also add
an authored in-game interface that independently selects an operation useful
for reading them?

This is a clue search, not a claim that every contemporaneous secret is part
of one combined theory.

## Evidence boundary

- Independently verify the two depot manifests and their dates/branches.
- Reproduce the executable Eye-constant fingerprint and WAK census only if
  both historical payloads can be obtained.
- Until then, label the reported `284/284`, `1402 added`, `145 removed`, and
  `980 changed` counts as externally reported, not reproduced.
- The Discord report's named files were selected after seeing the Eye target.
  Their names and visual resemblance have no statistical weight.
- Inspect current copies only as implementations that may preserve the 1.0
  mechanism; do not infer their historical bytes without the 1.0 WAK.

## Target-blind candidate rule

Rank every reported addition or changed subsystem by the following observable
interface properties, before comparing its values with the Eye corpus:

1. It accepts a player-controllable or world-state input.
2. It produces a finite, repeatable readout, ordering, state transition, or
   persistent flag.
3. Its authored alphabet or state space has a natural, non-fitted relation to
   the Eye representation: five directions, nine panels, or 83 used labels.
4. The operation can be stated from the asset or script alone.

Decorative images, names containing `eye`, and generic 1.0 content score zero
unless they participate in such an interface. A candidate must stand alone;
partial matches from different candidates are never combined.

## Frozen evaluation

For each surviving interface:

1. derive one complete mapping from the asset/scripts without Eye fitting;
2. state one Eye consequence before calculating it;
3. test the consequence against a matched null or exhaustive control;
4. require a planted positive control for any new detector;
5. promote only exact replay, a strong held-out prediction, or a
   decoder-independent selector of an already defined operation.

If no candidate reaches step 1, close the interval as an inventory negative.
If historical payload access remains unavailable, do not promote file-level
chronology or absence claims.
