# Forty-sixth wide horizon — axis-typed branch machines

## Why this is a new batch

The existing work already closes ordinary reset automata, predictive Hankel
rank, graph coverings, typed Dyck stacks, rotor schedules, direct `5×5`
geometries, adaptive cache allocators, and affine cross-panel carriers. This
batch does not enlarge any of those models.

The remaining positive object is the locally canonical equality-class program
after the independently selected final-row phase entry. Its first 30 events
allocate all classes `0..24` and probe five old classes. The established
middle-coordinate probes form a physical counterclockwise direction cycle.
The new question is whether the post-30 branch is a typed *program record*
rather than another substitution table.

The principal branch pattern below was inspected before this freeze. All
frequencies are therefore conditional audits, not discovery p-values.

## Inspected branch that motivates A–C

The header topology fixes:

```text
loop         E4
source mate  W4
target mate  E5
```

The three late signatures share 30 events. E4 and W4 then stay together while
E5 takes the other branch. At positions `30..32` the local class words are:

```text
source pair  2,25,20   = 002,100,040 in base five
target mate 25, 3,16   = 100,003,031 in base five
```

They rejoin at position 33. The ordinary sums are `47` and `44`, giving the
inspected residual `+3`.

This is more constrained than an arbitrary numeric anecdote:

- class `25 = 100_5` occurs once on each side and cancels;
- classes `2` and `3` are positive third-coordinate direction states;
- the class IDs are the same canonical coordinate system already selected by
  the independently established middle-coordinate wheel;
- `+3` is the fixed later Gate operation already executing the header/phase
  cycle.

It is still not a decoder. Lane B must determine whether the next closed
branch record is predicted rather than merely fitted.

## Fixed calculations

- Use `late_signatures()` and the phase boundaries already derived elsewhere.
- Use the header-selected loop/source/target roles; do not search panel
  orientations.
- A closed disagreement window is a maximal aligned unequal run followed by
  equality before the shorter stream ends.
- Window checksum is the ordinary integer sum of local class IDs, reduced
  modulo 83 only for reporting. No positional weights are fitted.
- Base-five class digits use weights `25,5,1` in the accepted eye order.
- The systematic-code holdouts are class 10, the independently selected
  source exit, and class 24, the independently selected first occurrence at
  position 28.

## Branching rule

Run all six screens before deepening any one.

- If A and B both pass, freeze the exact branch rewrite and seek a consequence
  outside the two inspected windows.
- If only `+3` survives, retain it as Gate corroboration but not a machine.
- If D or E fails, close that entire strict family rather than adding state.
- A result may guide plaintext work only after it predicts an unseen equality,
  marker, boundary, or visible label.
